# 安徽单招信息查询站

面向安徽省高职分类考试（俗称"单招"）考生的纯静态信息查询站：74 所院校、1941 个专业的招生计划、学费、历年分数、录取概率与报考辅助工具。

- **源码仓库**：https://github.com/heyanxingyan/anhui-danzhao （public，默认分支 `main`）
- **线上地址**：https://heyanxingyan.github.io/anhui-danzhao/ （GitHub Pages，已开启）
- **备用域名**：仓库内有 `CNAME`，历史上还部署过 `anhui-danzhao.surge.sh`（Surge 部署脚本见 `_dev/deploy-surge.js`）
- **技术栈**：原生 HTML + CSS + JavaScript，**无框架、无构建步骤、无后端**。改完文件直接发布即可生效。
- **目录约定**：`index.html` 等 23 个页面 + `js/data.js`（全部数据）+ `js/app.js`（全部逻辑）+ `css/style.css`；`body` 上的 `data-page="xxx"` 是路由键，`app.js` 末尾的 `handlers` 表按它分发渲染函数。

## 日常运维

所有脚本都用打包自带的 Node 运行（本机 **没有** 全局 node/git/python）：

```powershell
$node = "C:\Users\Admin（无密码）\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\node\bin\node.exe"
```

| 目的 | 命令 |
|---|---|
| 本地预览（带 gzip） | `& $node tools/serve.js 8899` → http://127.0.0.1:8899/ |
| 数据体检（计划/学费/分数/停招/重名） | `& $node tools/audit-data.js` |
| 静态一致性（语法/资源/死链/DOM） | `& $node tools/static-checks.js` |
| 与线上逐文件比对 | `& $node tools/compare-remote.js` |
| 查当前缓存版本 | `& $node tools/bump-cache.js --check` |
| 抬版本号 | `& $node tools/bump-cache.js 20261016a` |
| 发布（需 GITHUB_TOKEN） | `$env:GITHUB_TOKEN="…"; & $node tools/release.js --dry-run` |

### 标准发版流程

```powershell
# 1. 改数据/页面
# 2. 抬缓存版本号（**必做**：不抬的话用户会继续拿到旧 data.js）
& $node tools/bump-cache.js
# 3. 跑体检，必须全绿
& $node tools/audit-data.js
& $node tools/static-checks.js
# 4. 本地预览确认
& $node tools/serve.js 8899
# 5. 对比 + 发布
$env:GITHUB_TOKEN = "新token"
& $node tools/release.js --dry-run
& $node tools/release.js --message "2027政策更新"
```

> **为什么不用 git**：这台机器上全盘找不到 `git.exe`（`C:\Program Files\Git`、scoop、choco 路径都没有），所以发布走 GitHub Contents API —— 每个文件一次提交，没有真正的 git 历史与回滚能力。**建议装上 git**，之后把仓库改成标准 `git push` 流程，这是我认为最值得补的一件工程基建。

### 院校详情「考试类别 + 考纲」功能说明（`20261015n`）

**为什么按类别分组、而不是每行写一遍考纲**：同一专业组的考纲是同一段文字，铺到 78 个专业行里会把同一段话重复 78 遍。所以组头只写一次类别名 + 考试形式，点击展开完整考纲。

**数据来源与纪律**：`js/exam-groups.js` 按院校 id 存 `{ gaozhong, zhongzhi, special, sources, confidence }`，每个类别含 `name / form / content / majors / categories / source`。全部逐校联网核查官方章程与考纲原文，**查不到就留空并写 note，绝不编造**。

**专业归属的两条路径**：
1. `majors` 声明具体专业名（首选）
2. `categories` 用 19 个大类 key 兜底。**同一大类不能同时挂在两个组下**，否则会因"先命中"而错分——这是实际踩过的坑（合肥财经的旅游管理一度被归到财经商贸类）。

**合并工具**：`tools/merge-exam-groups.js` 读 `tools/_exam_research/batch_*.json`，做四类自检后才允许写入：组名/考纲内容/来源 URL 是否齐、**声明的专业名能否匹配上本校专业**、大类 key 是否合法、有无院校被漏掉。

**一条重要的核查结论**（来自 batch_C 的 24 所）：**普高几乎不分专业组、统一试卷**（24 所中仅芜湖职业技术大学按招生类别分场次）；**分组全部发生在中职（职业技能考试）**，命名方式有「类别一…九」「专业模块一…十」「职业技能考试一…十」等。

### 已知坑（写给以后改这个站的人）

1. **`</div>` 写在字符串里会提前闭合 `<script>` 标签**。HTML 解析器不认 JS 字符串，`app.js` 里生成 HTML 的模板字符串必须写成 `<\/div>`，否则整页空白、控制台报 `Invalid or unexpected token`。
2. **顶层 `const` 不挂到 `window`**。用 `typeof w.COLLEGES` 在 iframe/其他上下文里探测 `data.js` 是否生效会永远得到 `undefined`，那是探测方法错了，不是数据没加载。
3. **iframe 的 `load` 事件会先为 `about:blank` 触发一次**。等一次 `load` 就 resolve 会拿到空文档，必须轮询到目标页面真正就绪（`probe-harness.html` 已按此实现）。
4. **`data.js` 是一行行的超长 JSON**，用 `Get-Content`/`Set-Content` 往返会破坏 UTF-8 编码；改它请用 `write`/`edit` 工具或 Node 脚本。
5. **PowerShell 的 `Invoke-WebRequest` 在本机 TLS 直接用不了**，联网核查请走 Node 的 `fetch` 或 `web_fetch` 工具。
6. **正则的过滤条件定太严会静默丢数据**。核对专业名时用 `[\u4e00-\u9fa5]{3,}` 把「护理」这类两字专业名整个漏掉，且不报错——一度因此误判"护理不存在"。**凡从文本抽名称，长度下限一律给 2，宁可多报再人工筛。**
7. **省考试院的章程 PDF 不适合程序解析**。它没有 ToUnicode（字符要靠内嵌字体程序反推），且每个字一个 `BT…Tm…Td…Tj…ET` 块、文本矩阵跨块累加，坐标无法还原成表格列（折腾 7 轮未果）。**要计划表就去学校招生网找 HTML 或学校自制的 PDF**——学校自制 PDF 通常有 ToUnicode + 矢量表格线，可以提。工具与结论见 [tools/PDF-表格提取说明.md](tools/PDF-表格提取说明.md)。
8. **`bump-cache.js` 不带参数时，可能一个版本号都不抬**。它按"当天已用到的最大字母 +1"生成新版本，如果当天已经用到 `z`，就没有下一个字母可用，输出「已把 **0** 个 HTML 的版本号抬到 …」。此时 `release.js` 只会更新改动过的资源文件，**HTML 里的 `?v=` 不变 → 浏览器继续命中旧缓存 → 用户看不到改动**（表现为"我改了但线上没变"）。改完东西要发布时，**带上明确版本号**：`node tools/bump-cache.js 20261016a`。
9. **增量发布会把版本号搞散**。`release.js` 只上传与远端不同的文件，而每次 `bump-cache.js` 都自增一个字母——于是没被改动的页面版本号停在旧字母上，全站出现 `w/x/y` 混杂，各页面按自己的版本号拿到不同代资源。发布后建议核对一次：`node tools/bump-cache.js --check` 应报告"当前版本：X（N 个 HTML 含版本号）"且只有一种。
10. **CSS 曾经完全不参与缓存击穿**（2026-10-16 修）。所有页面引用的是 `css/style.css`，**不带 `?v=`**，而 `bump-cache.js` 的正则 `/\?v=(\d{8}[a-z])/` 只抬"已带版本号"的引用——于是改 CSS 时工具一声不响地什么也没做，老用户浏览器里始终是旧样式。表现是：「我改了样式，本地正常，线上别人看到的还是旧的」。现已给全部 CSS 引用补上 `?v=`，并在 `bump-cache.js` 里加了裸 CSS 引用的处理分支。
11. **别拿部署前的页面下结论**。GitHub Pages 的 CDN 传播通常 30-60 秒，浏览器还可能hold住旧 HTML；发布后立刻验证会看到旧 js/旧 CSS，误判成"没生效"。验证前先重新打开页面（可带个 `?nocache=1` 之类的查询串），或先 fetch 一下线上文件确认版本号。
12. **发布必须走单次原子提交**（2026-10-16 修）。`release.js` 原来对每个改动文件调一次 `PUT /contents`，每个都是一次独立 commit。抬一次版本号要动 22 个 HTML → 22 个 commit → GitHub Pages 触发 22 次构建，它们互相踩踏，结果全是 `Page build failed`，而**旧文件照常服务、新文件永远 404**——表现是"发布报告成功，线上却没这个文件"。现在用 Git Data API：一次性 `POST /git/trees`（带 `base_tree`）+ 一次 `POST /git/commits` + 一次 `PATCH /git/refs`。发布后如仍怀疑，查构建状态：
    `GET /repos/:owner/:repo/pages/builds` —— `errored` 就是没部署上去。
    **注意**：原子提交只是把"一次发布 = 一个 commit"做到，但**连着发布多次仍会踩踏**。构建历史里 `errored` 的 `duration=0ms` 且成簇出现，就是短时间内多 commit 被互相取消的特征。发布之间留出间隔，别连着推。
13. **⛔ 曾把 5 个 0 字节页面推上线（2026-10-16 事故）**。本地 `about.html`/`benke.html`/`college-detail.html`/`college-list.html`/`compare.html` 被清空成 0 字节（原因未查明），`release.js` 照常把它们提交上去 → **线上这 5 个页面变成全白**。恢复方式：用 git blob API 从历史提交里取回脚本/页面内容，不要凭记忆重写。
    现已加防线：`release.js` 发现 `.html/.js/.css` 为 0 字节时**直接拒绝发布并退出**，并列出文件名。
    **补充（2026-10-17）**：清空是**间歇性反复发生**的（同一天又清空 `college-detail.html`、`category.html` 各一次，且恢复后可能立刻再被清空）。
    发布前扫一次不可靠，**真正的保障是发布脚本内置的那道检查**（在读取文件的那一刻判断）。
    另配了自愈守护进程 `tools/watch-empty-files.js`（每 3 秒检查 34 个 HTML/JS/CSS，发现 0 字节即从远端或历史提交取回）。
14. **⚠️ data.js 末尾有一段「估算层」会编造数据**（2026-10-17 发现并处理）。
    它用 id 取模给缺字段生成看起来很真的值：

### 这次数据修复的方法论（以后遇到同类问题照做）

1. **优先找学校招生网的 HTML 表格**；其次**学校自制 PDF**（有 ToUnicode + 矢量表格线，可解析）。
   **省考试院的章程 PDF 不要用来提表格**——无 ToUnicode、每字一个文本块、坐标不可用（详见 [tools/PDF-表格提取说明.md](tools/PDF-表格提取说明.md)）。
   不少学校的计划表是**内嵌图片**，那就放大逐格抄。
2. **抄完必须做列和校验**：各专业普高求和 == 章程自报的普高总量（中职/退役/老区同理）。
   **对不上就说明抄错了，不能交差。** 这条校验抓出过真问题：
   - 安庆：中职差 30 → 顺着差找到漏抄了一行「机电一体化技术（高职专业学院-太湖职业技术学校）0/30」。
   - 审计：中职差 1105 → 定位到 5 个"高职专业学院"行被整批漏录；老区差 50 → 该 5 行各有老区 10。
3. **同一专业出现两次是正常的**（"高职专业学院—某中职学校"联合培养，同一专业不同就读地点），
   **必须分两行**，名称里带上培养地点（如「航海技术（高职专业学院·铜陵理工学校）」），否则站点判"专业重名"错误。
4. **整表重建优于逐条打补丁**。安徽交通库内 45 条里有 28 条官方 2026 计划表根本没有、数字还呈模板化
   （大量 40/15、50/20），逐条修只会越修越乱；用官方 38 行整表替换才干净。
5. **一切数字取自官方原文，不推测**。官方表没有专业代码/学费列时写 `null`，不用目录码硬凑。
   这批 14 所里**绝大多数官方计划表都没有专业代码列**，也没有分专业学费（学费列是整列合并的
   "按照省价格主管等相关部门核定标准执行"）。
6. **注意别把"高考计划"当成"分类考试计划"**。徽商的分类型缺专业清单里混进过 6 个只存在于
   **普通高考**计划的专业（机场运行服务与管理、汽车技术服务与营销等）——分类考试 2026 就是 26 个专业。

### 对比页瘦身细节（`20261015m`）

**根因不是"表格太大"，是一行太高**。用浏览器逐行量高度后发现：

| 行 | 修复前 | 修复后 |
|---|---|---|
| **2026预测分** | **1152 px** | 24 px |
| 2026计划 | 157 px | 24 px |
| 录取规则 / 校考占比 | 99 px | 24 px |
| 招生办电话 / 在校生规模 | 79 px | 24 px |
| 其余 9 行 | 40 px | 24 px |
| **文档总高** | **2429 px** | **843 px** |

`score2026` 这个字段全站 74 所**都是段落**（0 所是纯数字），其中 37 所含数字。原代码直接 `row('2026预测分', c => c.score2026)` 把整段塞进单元格，于是那一行涨到 1152px——这才是"要滑半天"的真正原因。

修法：

1. **`compactScore2026()`** 把长文压成"短值 + 来源标签"：优先取校考合格线数值（如 `150 分` + `校考线`），其次任意"普高/中职…N分"，没有数字就只给 `未公布` 标签，**绝不把长文放进单元格**；完整原文放 `title` 提示。
2. **行数 15 → 11**：把"招生办电话 / 在校生规模 / 就业率 / 专升本率"移入可折叠的「更多」区（默认收起），展开才显示 4 行。
3. **行高 40 → 24px**、字号 11px、`table-layout: fixed` + 单行截断，`录取规则`/`2026计划`/`校考占比` 用 `title` 保留全文。
4. **表头校名缩写**（去"职业技术学院/职业学院/高等专科学校"等后缀），完整校名放 `title`；否则 4 列时表头要换 2 行、行高 92px。
5. **表格容器固定高度 + 内部滚动**：`max-height: calc(100dvh - 140px)`（`vh` 回退），整页不再变长，滚的是表格，**底部 Tab 栏始终在屏幕上**。
6. 本页隐藏页脚导航与署名水印（`body[data-page="compare"] .foot-nav/.site-footer { display:none }`），导航栏改为 sticky。

**390×844 实测（2 / 3 / 4 所院校三种情况）**：文档高 843 ≤ 视口 844，无需滚动页面；表格内容 343px 完整显示不触发内部滚动；横向溢出 0；无任何单元格被截断；底部 Tab 栏在屏内。


### 录取概率页修复细节（P0-1/2/3）

**旧逻辑的致命缺陷**：`calcTotalScore` 只用 3 条精确字符串匹配（`文化×40%+校考×60%` 等），其余 31 所全部落进"文化+校考直接相加"兜底分支。这不只是算错，而是**把 0-100 的百分制合成分与 0-600 的直接相加分放在同一根坐标轴上比**，结论方向都会反。

例：安徽水利水电「文化300分 + 校考300分 = 总分600分（直接相加，**各占50%**）」——
旧代码按相加处理，文化200+校考200=400 当成 600 分制看，判"稳"；实际该校是百分制合成，正确结果 67%。

**新实现**按章程原文把规则归成四类，判据都是原文明确措辞：

| 类别 | 判据 | 坐标轴 | 你输入的分 → 等效分 |
|---|---|---|---|
| `sum` | 原文写「直接相加」 | 章程声明的总分（600/700/750） | 文化 + 校考 |
| `weightedScaled` | 带权重且章程声明了总分 | 章程总分 | 两项按权重归一化后映射到该轴 |
| `percent` | 带权重但章程未声明总分（或已自行折算百分制） | 100 | 折算百分制 |
| `examOnly` | 「文化过线后按校考成绩排序」 | 100 | 校考得分率 |

**权重从哪来**：只从"公式句"里取（含 `×N%` 的那一块，跨 `；` 时合并到括号配平），归属按"离 `%` 最近的分项名"判定。分项满分另走一套提取，并显式排除两类污染源：

- **年份**（`（2026章程）` 的前三位"202"曾被当成满分，多所院校算出 202）——先把年份等长屏蔽；
- **总分**（`校考300分…= 总分600分` 里的 600 曾被当成校考满分，把 600 分制算成 900）——用 lookahead 排除。

**校考滑块上限**随之对齐坐标轴：`sum`/`percent` 用章程分项满分；`weightedScaled` 按校考在合成分里的占比折算（如权重 90%、总分 600 → 滑块满分 540）；`examOnly` 用校考满分。这样"文化填满 + 校考填满"恰好等于总分上限。

**验证方式**：`tools/verify-composition.js` 从 `probability.html` 里抽出真实内联脚本求值，对 74 所院校逐一比对一张**逐条抄自章程的期望表**（模式 / 文化权重 / 校考权重 / 坐标轴），并断言"满分输入不得超过坐标轴上限、不得出现负值或 NaN"。

```
✅ 74 所院校的模式、权重、坐标轴全部与章程原文一致
✅ 74 所院校在普高/中职两种类别下，满分输入均不超过各自坐标轴上限，且无负值/NaN
```

### 遗留的小不一致（不误导用户，但口径不统一）

少数院校章程里写了「校考满分 300」，同时又说「×2 折合 300 分制」，导致同一项有两个数字。此时坐标轴按"文化满分 + 校考满分"取，可能略大于章程声明的总分（如安徽审计：300 + 150 → 450，章程另有"满分折合300分"字样）。这类校的滑块满分偏大一点点，但**结果与概率方向都是对的**、且不会出现超上限的分数。彻底消除需要给每所院校显式存一条结构化规则（见待办 P0-3 的说明）。
